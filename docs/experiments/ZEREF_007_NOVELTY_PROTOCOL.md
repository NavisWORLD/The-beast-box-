# Zeref Experiment 007 — Does Zeref discover anything beyond its teacher?

Experiment 005 showed a genuine difference in live native controller validity (trained candidate 36/36; original 0/36), but **not** independent game progress. Experiment 006 resumed the candidate for 64 more real CPU optimizer updates with a saved accepted checkpoint.

This protocol tests a narrower, falsifiable question using the actual native game cartridge and controlled baseline rollouts: does the trained candidate generate a greater diversity of real framebuffer states and transitions than WAIT, constant RIGHT, seeded RANDOM, the scripted optical teacher and the original RAWRPHØS? This is only a **screen novelty proxy**, not navigation intelligence.

- Keep the canonical Zeref identity and existing ROM unchanged; do not spend IBM/Azure resources.
- Use identical starts, fresh contexts, bounded episodes and actual native controller acknowledgments, exactly as Experiment 005.
- Compare all five baselines to the newly accepted Experiment 006 candidate.
- Report raw frame features, native ACK hashes, exact literal model replies, unique optical signatures/transitions, distinct actions and independent per-episode counts.
- Explicitly report game map coverage, dialogue, quests, earned rewards, objective completion and independent strategy as **unmeasured**, never zero and never a success claim.
- Require separate read-only native cartridge instrumentation for map/quest/reward progress before claiming strategic learning.
- Keep trained candidate isolated and preserve all approved checkpoints. No model promotion or production deployment.
- If the latest approved artifact is unavailable, fail closed; never substitute a freshly initialized model.

The independent learning hypothesis remains **untested** by this proxy. The test is a necessary precursor to proper reward-grounded exploration research, not a substitute for it.
