## Confirmed source-wiring concern

COSMOS 009 explicitly constructs `AdaptiveControl(RefractiveMemoryRouter(SimpleNamespace(memory=...)), r12_state=initial_r12_state(), dyn12=[0.0]*12)` and leaves controller `sequence=0`. Initial R12's `reality_coupling=0` makes the source's `refract` operation an identity. The controller is trained on the *unrelated original sawmill/turtle/orchid* fixture but tested on newly generated notebook numbers. No actual product `CNS.tick` or sensor/state feedback runs in 009. The isolated `AdaptiveControl` recalculates ranking by trained component weights; production `DurableRuntime._route_memories` directly calls the original `RefractiveMemoryRouter.rank` with static module weights and does not automatically install these trained control weights. Therefore 009 is **not** a full COSMOS closed-loop integration test; its numeric result remains valid for its tested isolated configuration.

An independent **actual product DurableRuntime** synthetic-only canary writes one fake record and runs two genuine `respond` turns with a deterministic fake provider. It checks product `CNS` tick and evolving `dyn12` alongside the original `r12_state` SHA/sequence and route receipts. As of this exact preflight source, actual product `r12_state` has no in-turn transition in `DurableRuntime._respond_event_serial`, so it retains initial sequence zero and zero reality coupling even when CNS advances. This is a verified **missing handoff**, not a conclusion about original research ideas. R12's formula intentionally prohibits synthetic events from fabricating measured reality coupling: any later fix MUST respect that provenance rule, never fake `provenance_class="measured"` from a synthetic notebook and never create unearned quantum/physical claims.

The *original 009 fixture* was also extremely easy for lexical matching because query and target text repeat the invented notebook identifiers. The prior 009 actual source run found lexical 100% top-1 on these data but COSMOS R12/adaptive much worse. That identifies a **benchmark/feature alignment and training-domain transfer failure** in the tested harness; it cannot establish that a different, actually aligned real product configuration would or wouldn't do better.

## Mandatory calibrated model upper bound BEFORE changing retrieval

009's independent 2×2 original real-model inference jobs completed but original generated answers were zero/nearly zero even with oracle correct context. Accordingly this experiment isolates whether the problem is **model ability, original prompt, 18-token budget, or overly restrictive first-line score**, rather than claiming retrieval is the only bottleneck.

Reuse exactly original seed **17**, original eight-record short fixture, first **four** original 009 synthetic gold queries in unchanged frozen iteration order. Use only the original checksum-pinned existing independently pretrained SmolLM2-135M-Instruct and Qwen2.5-0.5B-Instruct, exact original upstream revision and full safetensors SHA verified before inference, all model tensors SHA unchanged after inference. Each original model is tested on all 4 cases × 4 diagnostic prompts × **18 or 80 greedy generated token budgets** (32 per model), CPU only. The four *frozen diagnostic* input conditions are:

1. `copy_seed`: actual correct oracle source, ask only for the documented three-digit seed without arithmetic. Tests whether the actual model can **read a perfectly retrieved source**.
2. `arithmetic_only`: give actual seed and required offset explicitly as a standalone simple arithmetic expression, no retrieval. Tests **model arithmetic/compliance** independently.
3. `original_009_oracle`: original verbatim 009 prompt with exact true oracle record. Reproduces prior problematic generation geometry with two budgets.
4. `structured_011_oracle`: same true source facts reorganized into explicitly labeled Name/Stored seed/Add fields with an explicit numeric output request. Tests **prompt structure** independently without altering the prior historical 009 task.

The strict first-nonempty-line scorer is unchanged from 009. A second independently frozen semantic first-line scorer also accepts only narrow complete phrases (`The answer is N`, `RESULT: N`, `original_seed + requested_offset = N` with EXACT expression operands) and NEVER accepts answer substring inside unrelated explanations or wrong arithmetic. Record both parsers and full literal output because all inputs are exclusively random synthetic fake notebooks, NOT owner data. Every result includes exact prompt SHA, original model SHA, input/output token counts, first-line strict and semantic correct flags, all negative results.

**Diagnostic logic locked before actual output:** poor copy_seed even at 80 means model+template+decoder can't yet reliably read oracle evidence; poor arithmetic_only but good copy means arithmetic is the bottleneck; improved structured vs original oracle indicates presentation/budget rather than all model incapability; strict 0 but semantic correct implicates formatter/grader. If one model reliably passes BOTH copy and arithmetic/structured oracle, a **separate preregistered 012** may then evaluate actual corrected closed-loop routing with strong lexical, original product R12, valid state transition, trained adaptive control and oracle; identical absolute questions/priors within each arm. Crucially this test does **not** train/select the scorer or original prompts based on test outcomes and is not evidence of 12D superiority or autonomous self-correction.

No rollout until independently reviewed staging with real durable-model state continuity and no alteration to frozen owner memory. Any production wiring change would need its own host-only opt-in, provenance validation, checkpoint rollback tests, provider authority separation and safe deployment approval.
