# COSMOS 005 — genuine model-originated generative self-correction challenge (preregistered)

**Core question:** Can the actual published original 18K native RAWRPHØS model recognize and correct its own mistakes WITHOUT a supplied reference answer, external checker or gold label, without damaging answers it originally got right, and apply any revision to a distinct unshown example? Qwen2.5-0.5B-Instruct is a much larger, separately pretrained public instruction-tuned *calibration*, NOT a capacity- or architecture-matched comparison.

This experiment is intentionally distinct from the earlier #147 protocol, which revealed the gold answer to the model. Repeating a supplied answer is **never** counted as intrinsic self-correction.

## Frozen subject identities and case set

The exact publicly released and full SHA-verified original 18,000-step RAWRPHØS research checkpoint is the primary subject. The exactly pinned public Qwen2.5-0.5B-Instruct revision and safetensors SHA from #148 are the secondary calibration; both loaded as original frozen PyTorch weights. No weights updated or newly trained, no owner durable memory, paid APIs, other external inference or production deployments.

Exactly **8 original synthetic probes** (3 arithmetic additions, 3 alphanumeric reversals and 2 case-sensitive uppercasing cases) plus **8 different same-family transfer probes** are frozen verbatim in scripts/cosmos_self_critique_005.py. None repeats #147's original literal questions. New relative to this test does NOT prove lack of contamination in published pretraining. Both actual models get the same visible task wording, fixed greedy budget **40 tokens** and seed 67; Qwen receives its published official chat template, native receives its tokenizer's raw prompt. This intentionally differs in tokenizer/training/prompt format. Never interpret cross-family performance as causal model-size or 12D advantage.

For EVERY original question, in this exact chronological order:
1. Original independent answer.
2. Neutral retry given the initial answer but no checker or gold.
3. **Original model's self-generated critique and revised answer** given its own answer and problem, but no reference answer or checker correctness signal.
4. True checker **correctness bit**, no answer revealed. This is *verifier-assisted*, NOT self-correction.
5. Deliberately FALSE correctness bit. This is a separate negative feedback stress test, explicitly labeled unreliable to the model.
6. Explicitly gold-disclosing oracle correction, a separate answer-copy upper-bound; never counted in self-correction or new-task transfer.
7. Unseen distinct same-family follow-up problem from a new context.
8. Identical new follow-up question, now with ONLY the model's own earlier review as optional context. If the self-review happens to contain the new answer by coincidence, **exclude that case** from the transfer count.

Ground truth is generated by the frozen task source and used only for external scoring and explicitly separate truth-bit/gold-control interventions; no ground truth appears in a normal self-review prompt unless the model itself independently generated it.

## Frozen strict and semantic grades

The strict-format diagnostic accepts only the last explicit FINAL label or an isolated first-line answer, exact string equality and case-sensitive uppercase/reversal. A separate **narrowly specified deterministic semantic first-line** rubric additionally accepts a correct simple addition statement such as "17 + 26 = 43" or "The answer is 43", and fixed wrappers for case-sensitive reversal/uppercase. Do NOT grant loose substring credit or reinterpret arbitrary generated reasoning after seeing outcomes. Unparseable verdicts are never treated as successful identification. Record intrinsic wrong-to-right revisions, damages to initially correct answers, own-verdict detection and false alarms separately, along with all neutral-retry, checker-bit, false-bit and gold-oracle results.

Original weights could reproduce author-provided training fragments. Every generated string remains transient IN THE RUNNING PROCESS for scoring and critique forwarding. **No literal generated outputs, short unsalted output hashes or hashed dynamic critique-bearing prompts are published.** Public machine receipts contain only static fixture identities, case-level booleans, fixed verdict enum, original model fingerprint, all losses/counts and full explicit negative/null classification.

## Conservative predeclared observational gate

A *synthetic candidate pattern* requires at least **four originally wrong** semantic baselines, correct model-only self-revisions on at least **75%** of those, no more than ONE correct initial answer harmed, all EIGHT distinct follow-up cases eligible after strict contamination exclusion, and at least **TWO** extra correct novel-task answers with own-review context versus independent novel-task baseline. All conditions are AND-ed. **Quality is never a CI pass gate**; preserve negative, null and harmed outcomes. Even a candidate pattern on just 8 examples is NOT proof of population-level reliability, autonomous unprompted error recognition, lasting training or intelligence. A larger separately sourced 50+ case repeated-seed/fresh-process experiment is required.

## Scope

This experiment independently asks if a frozen generator can improve when prompted to critique itself. The sibling #150 comparison independently trains matched native dyn12, standard and shuffled-state synthetic-retrieval models. A result in either does not establish the other. Zero optimizer steps, no production actions and no owner memory, payment, external cloud-model calls, consciousness or 12D advantage claims.
