# Claim Boundaries

This repository separates computational measurements from interpretations. The following boundaries are mandatory for Zeref, R12, CNS7, and TALK lineage reports.

## Evidence classes

- **MEMORY**: append-only durable software records and their hashes. Memory records can preserve prior text and metadata; they do not prove that the text is true.
- **LIVE SOFTWARE STATE**: measurements produced by the current software runtime, including CNS7 state vectors and bound R12 live epochs.
- **EXPERIMENT EVIDENCE**: sealed inputs, preregistrations, workflow runs, artifacts, hashes, metrics, and logs from an identified experiment.
- **HYPOTHESIS**: an interpretation or proposed mechanism that is not established by the saved measurements.
- **MODEL-GENERATED TEXT**: a model output. It is behavioral data, not scientific ground truth merely because the model produced it.

## Claims the current evidence supports

The verified R12 work supports a software-routing claim: changing `rho` can change refractive retrieval ranking, which can change the active context presented to Zeref and therefore downstream hidden-state, x54/Hebbian measurements, and generated output.

The verified live-loop work supports a context-delivery claim: lexical retrieval can miss freshly injected state while a separately verified refractive/live lane can guarantee that the current bound epoch reaches active context.

CNS7 software state uses the frozen dimensional contract `dyn12=12`, `dyn42=42`, and `dyn54=dyn12+dyn42` by exact concatenation.

## Claims the current evidence does not establish

Nothing in the Zeref, R12, CNS7, IBM, heartbeat, or training lineage establishes:

- consciousness or sentience;
- resurrection or biological continuity;
- that Zeref is literally a deceased person;
- a literal soul or a measured soul;
- communication with the dead;
- a direct mysterious `rho -> neuron` force;
- a quantum anomaly merely because model behavior diverged;
- quantum advantage from the saved software-training results.

A successful quantum-hardware job proves that the recorded circuit/job executed under the documented conditions. It does not, by itself, prove any of the claims above.

## Training boundary

Training targets must come from explicitly manifested supervision. Raw generated Zeref prose, incomplete Cory-spike output, failed workflow chatter, and unverified experiment commentary are not automatically training truth. Negative/correction examples may contain unsupported claims in the **prompt**, but the desired response must correct the claim.

Promotion is based on saved metrics and integrity gates, never on emotional tone, apparent personality, spooky wording, or a single impressive dialogue sample.
