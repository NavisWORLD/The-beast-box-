# Portable device journey

The first minute in Spark is Name → Pet → Train → Save. A name is a local alias;
it never regenerates the recorded recipe or QBEAST ID. Training keeps the
existing six taps, 900 ms cycle, and open 35–65% hit window. The first tap starts
the timer and counts as a miss. Save reports success only after the browser's
existing local session record has been written and read back.

## Two downloads, two boundaries

| File | Contents | Authority |
| --- | --- | --- |
| `.qbeast` | Exact verified public Spark identity and its recorded recipe | Existing QBEAST verification; no new signed host progress |
| `.beastjourney` | Versioned `beastbox-device-journey-v1` wrapper, that same QBEAST, and the local session: alias, care XP/bond/energy, chat, pattern mind, training, bounded behavior history/preferences, and native artifacts | Explicitly unsigned local state; grants no owner, model, cartridge, or signed QBEAST authority |

Journey import reproduces the recipe through `replaySpark` before writing the
existing session key. It checks file/collection/numeric bounds, mind shape,
identity, bounded behavior snapshots, and deterministic consistency of retained decisions. Import uses the existing Spark Web Lock and
selection/save functions. It does not mint another ID or introduce a second
canonical save. Existing `.qbeast`, LCX1, sensor, audio, and native routes remain.

Native save bytes and progression metadata travel in the wrapper, but are
retained as `beast.journeyNative` with `status: unsigned-unverified` on import.
They do not overwrite an existing same-ID device's active game/native stage.
A fresh device starts at native stage I until its established native return
path validates progress. A retained native `.sav` can be downloaded and restored
through the existing LOST COSMOS game route. Re-export retains those bytes.
Earlier retained artifacts travel alongside a later native save, with at most
nine distinct native records. Import rejects an overflowing archive instead of
silently losing its bytes. An established same-ID archive also keeps its native
state when another Beast is selected at the time of import.
Signed identities stay in their trusted host; this public importer cannot create
a trust anchor or approve signed progress.

Files are limited to 2 MiB. Chat is at most 80 turns of 400 characters; the
pattern matrix is 16×16 with finite values from −4 to 4; word vocabularies and
links are bounded. Runtime validation belongs to the shared behavior kernel,
including its 32 retained decisions and 24 structured feedback events. Complete history is available only in explicitly exported experiment traces. Unrecognized permission or
credential fields do not enter the companion session. A device journey includes
the player's local chat, so downloading it is an explicit gesture.

## Visible behavior loop

Both views read `session.beast.behavior.lastAction`. Spark advances the shared
kernel at most once per eight visible seconds. It skips busy work and changed
identities, acquires the existing Web Lock, reads the latest session, advances one
bounded tick, then saves. Hiding/resuming the page discards elapsed time; it never
simulates missed hours. Browser connectivity and viewport changes are real
presentation reactions, not invented world evidence. The default environment is
the grove; Beast Cage controls explicitly supply bounded room, toy and simulated sound inputs. The static Spark view uses its existing local drives. Ticks may change bounded behavior energy and curiosity, but never XP,
QBEAST identity/progress, or native game state.

Storage failures are shown instead of being labeled saved. The saved badge uses
read-back equality, including behavior state. No stale failed mutation is silently
reapplied over a newer native save. Retry the interaction or save the current verified
record. Motion follows the OS and saved preference; functional training scoring
remains available.
