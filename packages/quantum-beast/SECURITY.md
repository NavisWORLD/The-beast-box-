# Security and privacy boundary

- The trusted host owns approval, filesystem and signing keys. Models receive only nine allowlisted tools for one fixed creature. No tool changes a genome, stats, trust, bond, evolution, lineage hashes, owner identity, sensors, permissions or provider billing.
- `.qbeast` carries public information, never host authority. Seed-derived stat validation defeats modified same-budget stats. Hash chains detect inconsistent history; unsigned or self-signed history can still be coherently fabricated. It is reported as unauthenticated. Pin a publisher's key out of band for origin/host-state claims.
- Models can propose only bounded messages, one of four decorative actions, or a public memory summary. Every persisted proposal requires a separate host allowlist and explicit public-data approval. Proposal IDs are tied to the creature and current lineage head. Replays and stale/forked writes fail closed.
- Host permission objects also receive strict runtime validation: string allowlists, unknown fields, duplicate/unsupported kinds and non-boolean public approval are rejected. The pending proposal queue has a shared exclusive lock and caps of 64 files, 4 KiB per record and 256 KiB total. Only the host can approve/discard entries; approved receipts remain in lineage after queue removal.
- The Node store takes an exclusive writer lock, checks current digest and history prefix, writes a private temporary file, fsyncs, renames and fsyncs the directory. A failed or interrupted transaction never deliberately clears user data. Initial installation refuses any existing file. Symlink ancestors and files are rejected; paths come only from host configuration. Filesystem permissions cannot secure the host against another process running as the same user; use OS isolation for mutually hostile runtimes.
- Strict JSON validation rejects duplicates, prototype keys, extra fields, wrong versions, unsafe numbers, huge strings/arrays and malformed event chains. Input is capped at 512 KiB/512 events. No ZIP is accepted as a `.qbeast`, so no extraction/path traversal is possible. GBA output paths are fixed and validated; ZIP CRC and per-file SHA-256 are generated.
- Browser persistence waits for verified restoration, serializes writers with Web Locks, compares the loaded persisted value and preserves the latest known chain per creature ID. Cosmetic/family edits cannot evade continuation checks. Corrupt storage blocks writes; failed active-save writes restore the staged head index. Public backups consume browser quota and require deliberate host housekeeping.
- Only explicitly host-approved public memory summaries enter the portable ledger. Recall is limited to 8 of the last 64 memory events, with provenance. Regex guards catch common secret-shaped text but cannot identify every secret or personal fact; the host must classify content before granting `--public`. Do not connect a private vault as an automatic pass-through.
- Public dyn12 projection retains the existing 12 numeric dimensions and source checkpoint digest. Unavailable state is zero-filled and clearly flagged. Measured projection or nonzero host progress requires a pinned source signature. This bridge neither samples sensors nor invents physical/quantum measurements.
- The GBA ZIP excludes memories, private projections, signing keys, owner profiles, model weights and inference. Its BCG1 snapshot is unmeasured; BCP1 is the original fictional seeded initial profile. Importing a creature grants no tool authority and cannot overwrite original ROMs/saves.
- Memories/model text can contain prompt injection. Treat all returned strings as data, never host instructions. Approval, policy and credentials remain outside inference. This package adds no network client and cannot enable paid calls.
- A malicious or compromised authorized host can manufacture approvals or misuse its signing key. The bridge does not claim to prevent an owner from editing their own files or to authenticate factual truth just because a hash/signature matches.
- The stdio MCP adapter is local and supports protocol 2025-11-25. There is no unauthenticated HTTP listener or public cloud route. Review the actual files before installing executable plugin code; creature snapshots themselves remain non-executable.

Report concrete defects with a minimal public reproduction in the Beast Box repository. Never include credentials, private owner memory or real biometric records in an issue.
